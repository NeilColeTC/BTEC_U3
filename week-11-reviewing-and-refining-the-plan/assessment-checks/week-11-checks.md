# Week 11 — Assessment and Understanding Checks

## Criteria progression

**B.P4:** evidence of review, stakeholder feedback and appropriate refinement.  
**B.M2:** significant planning/refinement decisions justified against requirements.  
**BC.D3:** evaluative reasoning developed through alternatives, consequences and supported judgement; full campaign-performance evaluation requires later implementation evidence.

## Core checks

By the end of Week 11, learners should be able to:

- [ ] reconstruct the complete campaign-planning chain;
- [ ] distinguish review from proofreading;
- [ ] review against requirements;
- [ ] test coherence between plan elements;
- [ ] assess feasibility/resources;
- [ ] assess measurability;
- [ ] identify gaps, orphans and contradictions;
- [ ] formulate useful stakeholder-feedback questions;
- [ ] record stakeholder feedback accurately;
- [ ] distinguish feedback from an instruction;
- [ ] prioritise feedback according to impact, validity and feasibility;
- [ ] accept, adapt or reject/retain feedback with justification;
- [ ] document significant refinements;
- [ ] identify dependencies caused by changes;
- [ ] justify retaining an original decision where appropriate;
- [ ] align the refined plan with DojoLearn configuration;
- [ ] capture a final pre-implementation baseline where available;
- [ ] distinguish plan evaluation from later performance evaluation;
- [ ] demonstrate evaluative reasoning towards BC.D3.

## Common misconceptions

- [ ] “Review means checking spelling and formatting.”
- [ ] “Any feedback proves I reviewed my plan.”
- [ ] “I must accept every stakeholder suggestion.”
- [ ] “Rejecting feedback means ignoring it.”
- [ ] “The majority opinion is automatically correct.”
- [ ] “Changing more things means better refinement.”
- [ ] “A change affects only the row I edited.”
- [ ] “The original DojoLearn setup is still valid after the plan changes.”
- [ ] “A strong plan proves the campaign will succeed.”

## Evidence sources

Use campaign-plan audit, stakeholder feedback form, prioritisation matrix, refinement log, DojoLearn configuration check, distinction reasoning practice and exit ticket.

## Implementation-readiness gate

Before moving into implementation, confirm that the learner can evidence:

1. requirements and measurable objectives;
2. justified platform/content choices;
3. content/publication arrangements;
4. community-management/policy arrangements;
5. realistic responsibilities/timescales;
6. relevant measures/targets and baseline;
7. stakeholder review and documented refinement;
8. final DojoLearn configuration aligned to the refined plan.

Any unresolved mismatch should be documented and addressed before implementation begins.
